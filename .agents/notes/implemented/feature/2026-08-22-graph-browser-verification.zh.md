# Agent Note: Graph 浏览器验证

Status: implemented

[English](2026-08-22-graph-browser-verification.md) | 中文

## 问题

可选的 [Chrome DevTools 浏览器组合包](2026-08-22-managed-chrome-process-lifecycle.zh.md) 为 Harness agent 提供页面、截图、控制台与网络工具，但 Graph 规划尚未把浏览器验收识别为独立职责。主控可能省略真实 UI 验证、在集成构建可运行前分派验证，或把任务交给未获得目标 Origin 与视觉证据要求的通用验证角色。多个浏览器 Worker 还可能通过共享调试浏览器相互干扰，即使 Page ID 路由已经避免了隐式页面选择。

## 决策

Graph 默认团队加入已启用的 `browser-tester` 角色，并把并行上限设为一。其提示词把工作限制在分配的目标 Origin 与验收标准内，要求保留一个明确 Page ID，普通交互优先使用页面快照与元素标识；所选模型路由声明图片输入时，使用截图完成视觉断言。它会在关键操作后检查相关控制台错误与失败网络请求，并发布通过 Schema 校验的验证判定和可执行问题。它绝不输入真实 Secret、执行破坏性的生产操作，也不会关闭并非由自身创建的页面。

对于面向用户的 Web 工作与明确的浏览器测试请求，主控策略会把浏览器验证放在集成后的可运行构建之后。每个浏览器节点都会收到精确目标 Origin、关键流程、视口与 Locale 假设，以及可测量的 DOM 和视觉断言。用户提供且可访问的目标视为既有测试基础设施，不会因此调度环境变更。目标不可访问时会报告环境阻塞，而不是产品缺陷。

Graph Mode 不实现另一套浏览器协议。浏览器 Worker 会继承会话组合中的工具。启用 `@deepseek-ai/dsh-browser-chrome-devtools` 后，详细页面、控制台与网络证据保留在持久子会话中；截图结果通过既有附件路径进入支持图片的模型；只有结构化的已接受结果返回父 Graph Run。

文件证据使用相对于浏览器 Worker 会话工作区的路径。通用 MCP 桥接层会规范化每个已配置的浏览器文件系统路径参数，对照该确切工作区进行检查，并发送通过检查的同一规范目标，以避免进程 cwd 偏移和检查后的符号链接重新解析。缺失调用上下文、工作区外路径与符号链接逃逸会在调用前失败。固定版本的真实服务器目录测试要求每个已发现的路径类工具参数都受保护。隔离 Graph 工作区会把这些文件捕获为 artifact，再通过集成流程物化，因此 Worker 绝不会通过绝对路径写入源工作区。

## 考虑过的替代方案

**在 Graph Mode 内实现浏览器操作。** 拒绝，因为导航、选择器、截图、控制台观察、网络观察和 Chrome 生命周期已经属于维护中的 DevTools MCP 能力。

**把浏览器测试并入通用验证角色。** 拒绝，因为浏览器工作需要明确的目标、视觉、Origin 安全与页面所有权指令，并需要更严格的并发上限。

**让主控直接操作浏览器。** 拒绝，因为原始测试证据会进入父主控轨迹，绕过节点级重试与判定，并把意图分类与长时间运行的测试流程耦合。

## 后果

新 Graph 会话可以调度可审计的浏览器验收节点，且无需改变持久任务词汇。纯 DOM 检查仍可由文本模型执行，截图理解则要求精确模型路由声明图片输入。截图文件经过隔离工作区 artifact 集成后会保留为持久项目证据，同时不会授予跨会话文件系统访问权。角色级并行上限可以阻止同一 Graph 配置内的默认浏览器 Worker 并发，但不能提供跨会话页面所有权；并发 Graph 会话部署仍需隔离浏览器进程或外部分配策略。操作者仍负责启用浏览器组合包，并保护其目标 Chrome 与测试账号。
