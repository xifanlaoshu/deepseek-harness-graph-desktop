# Agent Note: 任务图设计与执行双视图

Status: implemented

[English](2026-08-18-dual-graph-design-and-execution-views.md) | 中文

## 问题

Graph 面板需要区分主控编写的任务定义与运行证据，同时避免在一个纵向工作区中重复渲染相同拓扑。节点证据与操作过于密集，不适合永久占用侧栏；但如果只能进入子会话查看，日常检查又会变得缓慢。

## 决策

会话 Graph 工作区包含两个主页签。设计页只显示所选不可变 Revision 的只读 Cytoscape 横向任务图。实现页左侧显示所选运行的任务图，右侧显示可滚动的节点摘要列表；每条摘要展示阶段、实际路由、精简结果与耗时。

选择实现图节点或摘要会打开弹窗，其中包含完整主控定义、输出 Schema、实际预算与路由、执行尝试、输出、产物、操作日志、Settlement、检查点、终态证据、子会话入口，以及当前节点状态允许的所有操作。任务修改、终止、重试、恢复、跳过、分派覆盖和替代输出都位于该弹窗内，使任务图可以占据工作区的大部分空间。

角色配置是 Graph 标题栏中的设置操作，不作为第三个主页签。设置弹窗保留既有的可丢弃草稿与显式保存语义。工作区、任务图、摘要、弹窗、按钮、输入框、下拉框和文本框统一使用 Harness 主题 Token、图标组件、控件高度、边框、圆角、间距与焦点状态。

只有当前页签会挂载 Cytoscape 实例。运行证据与节点选择更新会保留当前视口；选择另一个不可变 Revision 会创建新的布局并适应视图。浏览器计算的节点位置只属于展示状态，绝不写入会话日志。

## 验证

客户端行为测试固定两个页签、设计页纯任务图、实现页左右分栏、节点弹窗证据与操作、设置持久化、过期命令保护、视口生命周期与卸载行为。组装后的 Web Profile 使用真实任务图投影验证两个页签、节点弹窗、角色设置、响应式布局和 Harness 主题渲染。

## 考虑过的替代方案

**保留两张纵向排列的画布。** 这种方式可以同时对照，但会重复拓扑、减少任务图可用高度，并把节点记录与证据推到首屏之外。

**保留一张带运行装饰的画布。** 单张画布占用空间更少，却会混合主控意图与某一次执行，也无法让设计字段和运行字段拥有独立的视觉层级。

**在永久侧栏中保留完整节点详情。** 永久详情不需要弹窗切换，但即使用户只扫描拓扑也会持续挤占任务图宽度。摘要列表保留执行概览，弹窗则为密集证据与操作提供足够空间。

**在弹窗中复制完整子会话记录。** 子会话才是消息与工具事件的权威记录，因此不复制。弹窗只展示 Graph 自有证据并提供子会话入口。

## 后果

设计意图与运行状态拥有清晰且稳定的位置，实现图保留大部分横向空间，密集操作也不再与拓扑争夺版面。用户无法同时对照设计图与执行图，需要主动切换页签；查看完整节点证据需要进行一次选择。Cytoscape 视口状态只在单个页签生命周期内保留，不会跨页签镜像。
