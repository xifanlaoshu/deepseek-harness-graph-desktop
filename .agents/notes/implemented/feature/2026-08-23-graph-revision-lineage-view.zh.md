# Agent Note：Graph 修订谱系视图

状态：已实现

[English](2026-08-23-graph-revision-lineage-view.md) | 中文

## 问题

原有修订选择器只能用编号识别不可变修订，无法说明修订的具体目标、创建触发原因、与失败或被替代工作的关系以及执行成本。用户必须阅读主会话和子会话日志，才能区分新任务、主控重构计划和执行修正。把这段历史叠加到设计 DAG 上会混淆任务拓扑、设计演进和运行证据。

## 决策

本视图扩展[设计与执行视图](2026-08-18-dual-graph-design-and-execution-views.zh.md)、[人工控制与修订恢复](../../proposed/feature/2026-08-18-human-graph-control-and-revision-recovery.zh.md)和[渐进式规划检查点](../../proposed/feature/2026-08-18-progressive-graph-planning-checkpoints.zh.md)。这些记录继续保持有效，因为它们分别负责任务拓扑展示、变更语义和规划屏障。

Graph 工作区有三个一级视图。设计展示一份不可变任务图，执行展示一次 Run 及其节点证据，修订展示逻辑任务、不可变修订、类型化关系和派生运行指标。修订视图使用独立的只读 Cytoscape 画布，因为这里的节点是修订，不是可执行任务。

每个新接受的 `graph/submission` 可以携带版本化 `GraphRevisionLineage`。Host 根据主控决策和已接受会话状态生成权威记录。记录包含品牌化逻辑任务 ID、唯一分类、标题、目标、原因、创建者、触发证据、成功条件、关系，以及新增、修改、移除、保留和失效的节点 ID。执行时间、状态、子会话、尝试、Token、工具调用、重试和人工控制不能由模型输出提供。

分类为 `new_task`、`analysis_refactor` 和 `execution_correction`。新 Graph 是新的逻辑任务泳道。修订留在原 Graph 泳道，并通过 `refactors` 或 `corrects` 指向不可变父修订。Campaign 的 Batch 依赖会成为不同任务泳道之间的 `depends_on` 关系。Host 会拒绝把新提交分类为重构或修正、把修订分类为新任务、未知触发引用、不匹配的结构差异、重复节点 ID、无效文本或缺少父关系的提交。

回放时 lineage 字段是可选的，因为功能上线前创建的会话没有可信的分类证据。修订视图会把这类记录标记为“历史未分类”，不会推测其来源。这是数据完整性规则，不是新提交的兼容默认值。

## 投影和指标

浏览器确定性连接 Graph 修订、提交谱系、Run、节点尝试、检查点、控制记录和 Settlement。存在尝试时，开始时间取第一次尝试；否则取非 queued Run。结束时间要求所有已记录 Run 都进入终态。耗时等于结束时间减开始时间。子代理统计主子会话和续跑子会话的不同 ID；任务交互统计尝试次数；Token 和工具调用来自 attempt health；重试统计每个节点第一次以后的尝试；人工交互统计面向用户的控制和 awaiting-user 检查点。

缺失的遥测保持“不可用”。父 Graph 投影没有保存精确的子代理轮次数，因此抽屉显示不可用而不是零。完整消息和工具事件仍以子会话为权威来源；抽屉只显示安全的 submission、Run、control 和 Settlement 引用，不复制完整对话。

## 展示和导航

逻辑任务按照创建时间形成纵向泳道，同一任务的修订横向推进。带标签的曲线通过不同线型区分修正、重构、历史父关系和跨任务依赖，不只依赖颜色。选择修订后，右侧固定抽屉展示目标、创建原因、触发证据、任务图差异、Run、资源、关系和原始事件索引。关系按钮支持双向导航，包括从失败修订进入修正修订并返回。抽屉可以直接打开所选不可变修订的设计或执行视图。

指针悬停 360 毫秒后出现摘要预览。等价的有序按钮列表支持键盘和辅助技术导航。搜索覆盖任务文本、角色 ID、实际模型路由和错误码；修订类型与 Run 状态可以分别筛选。可见历史超过四十条时，默认保留第一条、当前条和最新二十条，用户可以展开完整历史。只有谱系拓扑或筛选变化才重建 Cytoscape，因此仅 Run 投影刷新不会重置视口。

## 验证

领域测试覆盖类型化谱系校验、无 lineage 的历史记录、临时提交身份和重复 Settlement 行为。主控测试证明 Host 派生的新任务和重构元数据、结构差异、不可变父关系及接受后回放。客户端测试覆盖第三个页签、运行聚合、不可用遥测、关系证据、返回设计视图、画布生命周期以及原有设计和执行控制。组装后的 Graph 快照覆盖模型可见的 `graph_submit` Schema 和主控流程。

## 考虑过的替代方案

**只保留修订选择器。** 选择器可以切换修订，但不能解释因果关系、独立逻辑任务、修正链和资源消耗。

**使用扁平时间线。** 纯时间顺序无法清楚表达修正谱系和跨任务依赖。

**装饰设计 DAG。** 任务节点和修订节点拥有不同身份与证据；合并会让两个视图都产生歧义。

**持久化浏览器位置或聚合值。** 布局属于展示状态，指标必须从权威事件回放；持久化任何一项都会形成竞争数据源。

## 影响

新会话拥有持久、经校验的修订解释和可导航的修正历史。历史会话仍可检查，但不会产生伪造语义。UI 可以聚合已复制到 Graph attempt 的遥测；在未来增加父会话安全的遥测事件前，精确子代理轮次仍显示不可用。搜索和有界展开让大型历史保持可用，同时不引入第二套持久化格式或第二种图渲染器。
