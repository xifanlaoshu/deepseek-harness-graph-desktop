# Agent Note：Graph 主控韧性与会话级压缩路由

Status: implemented

[English](2026-08-26-graph-controller-resilience-and-compaction-routing.md) | 中文

## 问题

Graph Mode 会把每次人工输入路由给同一个主控角色。主控模型可能拒绝已配置的推理强度、超过上下文窗口、在提供方重试后仍丢失数据流，或在判定输入前遭遇其他请求能力错误。无限重试同一路由无法修复能力不匹配；修改进程级已选模型又会改变无关会话，也不能可靠路由压缩所用的直接 `ctx.llm.stream()` 调用。

Graph 全局角色模板与会话 Graph 设置已经具有不同所有权：全局模板在首次启用 Graph 时复制，此后由会话日志拥有完整快照。主控恢复和压缩路由需要相同的历史隔离。它们还必须保留压缩保证：`llmStreamCall: true` 描述一次可重建的成功辅助调用；静默进行多模型摘要尝试会产生回放无法复现的未记录调用。

## 决策

`GraphModeConfig.controllerResilience` 是可选的会话级策略。新默认值启用策略但不包含高级路由；省略该字段会保留历史路由行为。策略保存有序的明确提供方／模型路由、相互独立的主控与压缩用途标记、可选推理强度、精确可重试失败码、每轮正数兜底上限，以及压缩阈值、保留比例、输出 token 和推理设置。

Graph 主控的 `agent/request-error` listener 会先调用 `next()`，因此现有提供方重试与上下文溢出压缩仍具有优先权。只有尚未处理且失败码已配置的错误，才能选择下一个主控路由并返回 `{ kind: 'retry' }`。路由序号仅属于当前轮次，同时受已配置路由数量和 `maxFallbackAttemptsPerTurn` 限制；后续轮次请求路由时会清除该状态。取消绝不会改变恢复状态或请求另一次尝试。主控角色的普通模型仍是首选路由。

压缩 Service Definition 新增与后端无关的 `compaction/policy` waterfall。`BasicCompactionEngine` 先解析普通的精确目标策略，再允许作用域策略插件替换完整的压力、保留、输出 token 与单一摘要目标决策。Graph Mode 选择第一个标记为压缩用途的路由；没有配置时使用主控首选路由。一个事务内不会尝试多个摘要模型，因此已存储的 `compaction/summary` 仍然只标识一次本地 LLM 调用与完整输出。

插件 Graph 设置页与当前会话 Graph 设置页使用同一个编辑器配置这些值。全局写入仍通过修订号保护，并且只影响此后首次取得 Graph 快照的会话。会话保存会追加一次经过校验的 `graph/config` 替换，并且只影响该会话。编辑器会规范化旧设置文档而不形成更新循环；只有保存后，旧文档才会获得新默认值。

## 考虑过的替代方案

**主控失败后修改进程级模型。** 拒绝，因为失败属于一个 Graph 轮次，而进程级选择会影响无关会话，也不会路由直接压缩调用。

**把每个主控错误都交给高级模型重试。** 拒绝，因为用户取消、错误的应用输出、权限失败与未知错误并不能证明另一个模型安全或有用。精确失败码准入和轮次级上限让升级保持有界。

**在一次摘要事务内依次尝试首选模型和所有压缩兜底模型。** 拒绝，因为只有成功的 `compaction/summary` 会持久化。失败的辅助调用对日志回放、token 计量与快照重建不可见。因此 Graph 会在可重建调用前选择一个高级压缩路由。

**每次请求都读取实时全局韧性设置。** 拒绝，因为后续设置编辑会在没有会话事件的情况下改变历史主控和压缩行为。

## 后果

主控能力错误可以在更强模型上恢复，而不会修改 Worker 分派或后续人工轮次。即使主控首选模型仍为本地模型，压缩也可以使用专用大上下文模型和更低的压力阈值。部署必须从模型目录明确选择路由并声明支持的推理强度；Graph 不会推断一定存在更大的模型。

该策略扩展了基础性的[会话 Graph Mode](2026-08-17-session-graph-mode.zh.md)与[压缩能力 seam](2026-06-18-compaction-capability-seam.zh.md)决策，但不取代其中的持久任务图、并发、表层替换或单次调用重建规则。提议中的[全局 Graph 角色模板](../../proposed/feature/2026-08-18-global-graph-role-templates.zh.md) Note 仍保持活动状态，因为其更广泛的角色 ID 确认与产品快照验收工作独立于本策略扩展。

## 验证

Graph Domain 测试会拒绝无效尝试次数、重复或无用途路由以及无效压缩比例，同时接受历史字段省略。主控测试证明下游恢复优先、轮次级升级、后续轮次回到首选路由、精确压缩路由和首次启用模板快照。Compaction-basic 测试证明会话策略会修改单次已记录摘要的路由与生成设置。客户端测试证明旧设置规范化，以及兜底与压缩值通过修订号保护完成持久化。
