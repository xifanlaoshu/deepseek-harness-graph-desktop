# Agent Note: 工具请求到达截止时间后退役 MCP 连接世代

Status: implemented

[English](2026-08-26-mcp-timeout-generation-retirement.md) | 中文

## Problem

MCP 服务器进程可能仍然存活，但某一次工具请求永不结束。SDK 截止时间只会拒绝调用方的 Promise，不会关闭传输。如果 supervisor 把进程关闭作为唯一的连接丢失信号，后续调用仍会路由到同一个不可用世代，因此每次重试都会再次耗尽完整截止时间，agent 可能持续陷入重复超时循环。

## Decision

MCP 桥接插件只把 SDK `RequestTimeout` 错误识别为工具请求到达截止时间。第一次到达截止时间会在错误传给模型之前隔离对应的确切客户端世代。通过该世代所属定义发起的新调用会立即以 `MCP_CONNECTION_UNAVAILABLE` 失败；并发到达截止时间的调用可以分别报告自身结果不确定，但不能再次启动退役。

连接 supervisor 会关闭已隔离的客户端，并在安排现有有界重连策略前等待传输所属的关闭信号。替代客户端会执行完整的工具发现，并原子替换旧定义。如果在现有世代关闭截止时间内没有观察到关闭，插件会停止重连，而不会允许服务器进程重叠。插件资源释放会同时等待截止时间触发的退役、连接和同步工作。

原始调用返回 `MCP_REQUEST_TIMEOUT`，并声明其远端结果未知。MCP 工具可能已经完成副作用，只是响应随后停滞，因此桥接插件绝不会自动重放该调用。调用方取消、服务器声明的工具错误和其他请求失败不会隔离正常世代。

## Alternatives considered

**让模型针对同一个客户端重试。** 该方案被否决，因为进程仍然存活不能证明其请求路径仍然可用，而且每次重试都可能耗尽完整截止时间，却不会产生恢复事件。

**重连后自动重试超时工具。** 该方案被否决，因为超时会让执行结果变得不确定；重放可能导致写入、提交或破坏性操作重复执行。

**在旧传输关闭前启动替代进程。** 该方案被否决，因为 stdio 服务器所有权包含其子进程和资源。重叠世代可能控制同一个外部系统，或留下孤儿进程。

**遇到每一种 MCP 错误都退役连接。** 该方案被否决，因为校验、授权和工具声明的失败都属于普通的单次调用结果，不能证明连接不可用。

## Verification

Supervisor 测试覆盖截止时间分类、中断期间立即拒绝、并发超时只执行一次退役、排除调用方取消、重连后执行以及现有关闭屏障。一个无需密钥的真实 stdio MCP 测试会运行响应永不结束的工具，对稳定超时诊断执行快照，并证明新启动的世代可以处理下一次调用。

## Consequences

发生 MCP 世代卡死时只会消耗一次配置的工具截止时间，而不会让每次重试分别消耗一次；现有重连预算负责恢复，无需增加新的策略配置。普通恢复期间工具注册保持稳定，但在替代世代的发现提交前，调用会快速失败。托管 MCP 服务器可能在退役期间关闭其拥有的资源；如果部署必须在 MCP 替换期间保留外部浏览器或服务，就应当由独立生命周期管理该资源，并通过传输端点连接。
