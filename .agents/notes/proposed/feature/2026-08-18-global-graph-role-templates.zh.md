# Agent Note: 带会话快照的全局 Graph 角色模板

Status: proposed

[English](2026-08-18-global-graph-role-templates.md) | 中文

## 问题

Graph 角色定义目前只存在于每个会话持久化的 `GraphModeConfig` 中。用户调整角色提示词、模型、推理强度选择器或团队成员后，必须在每个新会话中重复编辑。让会话实时读取全局设置虽然可以消除重复，却会让后续设置修改改变历史会话行为和回放结果。

## 提案

主设置界面将新增 Graph 角色区域，并由带版本的 `graph-mode` 设置命名空间支持。该区域编辑一个可复用模板，模板包含完整且有序的角色目录：稳定 id、标签、说明、控制器标记、启用状态、默认提供方／模型选择、推理强度选择器、角色提示词和角色并行度。属于这些模型选择的精确模型限额与模板一同编辑，使复制模板时保留其 OOM 防护。

编辑器支持新增、复制、排序、启用、停用和删除工作角色。它要求恰好一个启用的控制器和至少一个启用的工作角色，拒绝重复或不安全的 id，并禁止移除最后一个控制器或工作角色。控制器仍属于角色定义，而不是不可编辑的特殊表单；改变哪个角色担任控制器后仍必须只存在一个启用的控制器。模型选择使用共享模型目录；由于不同提供方接受的值不同，推理强度继续使用自由文本。“恢复默认”操作只在用户明确确认后恢复内置软件工程团队。

全局设置是默认值，不是实时父配置。当一个没有既有 `graph/config` 事件的会话启用 Graph Mode 时，Host 解析当前全局模板、完成校验、与内置调度默认值组合，并在控制器运行前向该会话追加一份完整 `GraphModeConfig` 快照。从这个提交点开始，会话只读取自己的 `graph/change` 事件。后续全局编辑不会追加会话事件、替换角色定义、改变模型路由，也不会影响任何已经持有快照的会话回放。

现有的会话 Graph 设置继续作为当前会话的显式覆盖编辑器。如果提供“将最新全局模板应用到现有会话”的操作，它必须是单独的用户操作，在追加新会话配置前预览角色增删、模型变化以及既有任务图修订中的引用。打开设置或编辑全局模板绝不会顺带执行该操作。

在全局编辑前已经创建但从未启用 Graph Mode 的会话不持有 Graph 角色历史；它首次启用时可以使用当时的最新模板。一旦提交过任何 Graph 配置，历史隔离规则永久生效。导入、回放和恢复不要求全局设置文档存在，因为完整角色快照仍保存在会话日志中。

## 当前实现

Host 维护带版本的 `graph-mode` 命名空间，并在首次启用时快照经过校验的模板。插件设置页提供不绑定会话的图形编辑器，支持角色新增、复制、排序、编辑、启用、删除、提示词、模型选择、自由文本推理强度选择、角色与模型并行度、全局准入限制，以及经过两次确认的内置团队恢复。写入携带已观察到的命名空间修订号；发生冲突时会保留草稿，并要求用户显式重新载入。组件、已装配客户端和 Host 集成测试覆盖编辑操作、模型目录加载、成功与冲突写入、非法模板、只读部署、设置不可用，以及全局编辑前后的会话快照规则。浏览器可见的快照覆盖和修改稳定角色 id 时更强的确认仍需完成，完成后本说明才能转为 implemented。

## 考虑过的替代方案

**每次控制器请求都解析全局角色设置。** 这种方式能立即看到全局编辑，却会在没有会话事件的情况下静默改变历史会话中模型可见的角色目录和路由，破坏回放与审计。

**只在全局设置中保存角色。** 单份数据避免重复，但导出或恢复的会话将依赖可变的机器本地状态，无法还原早期工作使用的提示词和模型。

**把全局模板复制到每个新建会话。** 这样可以提供严格的创建时默认值，但会向从未启用 Graph Mode 的会话写入任务图配置。首次启用时生成快照既能从第一个相关提交点开始保留历史行为，也避免无关的会话事件。

**保留固定数量的内置角色。** 这种方式更容易校验，却无法建立特定领域团队，并迫使未使用角色继续出现在控制器角色目录中。

## 验收标准

- 主设置界面包含 Graph 角色区域，可以独立于任何已打开会话编辑持久化全局模板。
- 模板编辑器支持角色新增、复制、排序、启用、删除、提示词编辑、模型选择、自由文本推理强度选择和每角色并行度。
- 校验要求恰好一个启用的控制器、至少一个启用的工作角色、稳定且唯一的安全 id、非空角色文本、有效模型选择和正数并行限制。
- 不存在既有会话配置时，首次启用 Graph 会在控制器请求看到 Graph Mode 之前追加一份完整且经过校验的快照。
- 已提交 Graph 配置的会话绝不自动读取或应用后续全局模板修改。
- 会话回放、导出、检查和恢复无需访问当前全局设置，即可还原角色目录、提示词、模型、推理强度选择器和限额。
- 当前会话编辑与全局模板编辑相互独立；任何显式的“应用到会话”操作都会预览变化并追加持久会话事件。
- 并发设置编辑器使用设置命名空间修订号，并在不丢弃任一编辑器草稿的情况下报告冲突。
- 面向用户的覆盖在全局编辑前后创建会话，并证明只有在编辑后首次生成 Graph 快照的会话获得新模板。

## 风险

两个包含相似字段的可见编辑器可能使用户混淆全局默认值和当前会话覆盖值；每个页面都必须注明自身作用范围，并显示会话是否已经持有快照。在全局模板中删除或重命名角色 id 可能使未来导入的任务图定义失效，因此 id 需要比标签更强的确认。已经配置的模型可能从模型目录中消失；设置页必须保留并标记不可用值，不能静默替换。把完整提示词复制到每个参与会话会增加日志体积，但这是确定性回放和历史隔离所必需的。
